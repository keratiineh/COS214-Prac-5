## 1. Project Overview

CampusGuard is a unified emergency-response coordination platform for a university campus. It coordinates communication, building physical access control, security dispatch, and medical triage during critical incidents while integrating legacy access hardware and preserving clean decoupling between all subsystem components.

## 2. Design Patterns Implemented (6 GoF Patterns)

| Pattern | Category | Lead Member | Key Participants | Purpose in CampusGuard |
|---|---|---|---|---|
| **Command** | Behavioural | Graeme (Member 1) | `OperatorCommand`, `DispatchUnitCommand`, `LockAreaCommand`, `IssueAlertCommand`, `OperatorConsole` | Encapsulates operator instructions as first-class objects with full history tracking and reversible undo/cancellation. |
| **Mediator** | Behavioural | Graeme (Member 1) | `ResponseCoordinator`, `CampusCoordinator`, `ResponseUnit` (Colleagues: `SecurityTeam`, `MedicalTeam`, `FacilitiesTeam`) | Decouples response units from direct many-to-many dependencies by centralizing coordination policies. |
| **Adapter** | Structural | Rati (Member 2) | `AccessControlSystem` (Target), `LegacyAccessPanel` (Adaptee), `LegacyAccessAdapter` (Adapter) | Translates high-level area string requests into legacy integer zone codes and status results. |
| **Facade** | Structural | Rati (Member 2) | `EmergencyOpsFacade` | Provides a unified, higher-level entry point for multi-step emergency workflows (e.g. coordinated building lockdown). |
| **Observer** | Behavioural | Angelo (Member 3) | `IncidentObserver`, `Incident` (Subject), `AuditLogObserver`, `DashboardObserver` | Automatically updates real-time operational displays and writes immutable audit trails on incident status changes. |
| **Strategy** | Behavioural | Angelo (Member 3) | `EmergencyStrategy`, `ActiveThreatStrategy`, `HazardContainmentStrategy`, `StandardTriageStrategy` | Encapsulates dynamic incident containment algorithms and allows runtime protocol switching without conditional ladders. |

## 3. End-to-End Demonstration Scenarios

The system runs two realistic runtime stories in `main.cpp`:

1. **Scenario 1: High-Threat Incident & Coordinated Multi-Pattern Lockdown**
   - An active security threat is reported in Engineering Lab 3.
   - `EmergencyOpsFacade` initiates a lockdown workflow coordinating three subsystem operations via `OperatorConsole` (`Command`).
   - The lock action is translated to legacy door hardware via `LegacyAccessAdapter` (`Adapter`).
   - `SecurityTeam` confirms the threat on scene and alerts `CampusCoordinator` (`Mediator`), which applies the `ActiveThreatStrategy` (`Strategy`) and stages `MedicalTeam`.
   - Every status transition automatically updates `AuditLogObserver` and `DashboardObserver` (`Observer`).
   - Security contains the threat, prompting the mediator to restore access and broadcast all-clear advisories.

2. **Scenario 2: Chemical Hazard, Medical Response & Failure Handling**
   - A hazardous chemical fire is reported in Chemistry Block B.
   - The coordinator applies `HazardContainmentStrategy`.
   - Error handling is demonstrated:
     - Duplicate dispatch of an already deployed team is rejected.
     - Locking an already locked area is rejected.
     - An accidental evacuation alert is cancelled and retracted using `OperatorConsole::cancelLast()` (`Command Undo`).
     - Modifying an already resolved incident is blocked.
   - Complete audit trail summary is generated by `AuditLogObserver`.

## 4. Build and Run Instructions

### Prerequisites
- C++11 compliant compiler (`g++`)
- GNU Make
- Valgrind (for memory verification)
- Docker & Docker Compose (for containerized demonstration)

### Method A: Running with Docker (Mandatory Demonstration Requirement)
To launch the complete application inside Docker as required by Task 6:

```bash
docker compose up --build
```

To clean up Docker containers:
```bash
docker compose down
```

### Method B: Building Locally with Makefile

1. **Compile the application**:
   ```bash
   make
   ```
2. **Execute the simulation**:
   ```bash
   make run
   ```
3. **Run Valgrind memory leak verification**:
   ```bash
   make valgrind
   ```
4. **Clean build artifacts**:
   ```bash
   make clean
   ```
